## 1. 用户意图与成功标准

用户已经明确：项目面向用户本人的深入、多维度分析，从 Codex、Claude Code、WorkBuddy、豆包、DeepSeek、千问办公等不同 AI 工具的会话中获取材料，形成有创意、针对实际痛点、值得体验的开源产品，并完成开发后发布到 GitHub。

产品主张：从长期 AI 会话中，看清自己反复卡在哪里、什么情况下做得好，以及这些模式如何变化。

完整个人档案覆盖目标与价值取舍、思考与决策、学习与协作、行动与成果、兴趣主线、阶段变化。首屏呈现少量值得深入查看的发现，每项都能回查原文、查看反例、接受本人修正。用户档案不代替现实证据，也不将 AI 产出自动视为用户能力。

首发默认选择：名称 SelfDiff / 见己、MIT 许可证、本地运行、中文优先并提供英文 README、不设置账号与云端数据库。上述属于待审阅的实现选择。

成功标准：

1. 无模型密钥也能完整体验合成示例，并完成导入、浏览、检索和资料管理。
2. 配置用户自己的模型后，真实会话能产生经过引用校验的个人档案与洞察。
3. 用户可以基于证据确认、修正、驳回结论，并比较两个时期的材料。
4. 数据不足或模型出错时明确说明，不能用演示内容填充真实用户结果。
5. 项目能够按 README 启动，关键自动检查通过，GitHub 上有可用源码、安装说明、示例和发布包。

## 2. 方案取舍

| 方案 | 优点 | 代价 | 决定 |
|---|---|---|---|
| 本地浏览器界面 + 本机服务 | 能读取本地 Agent 记录，资料集中留在用户设备上，便于审计和开源 | 开发涉及前端与本地服务 | 首版采用 |
| 纯静态网页 | 示例传播方便，导入流程轻 | 难以持续接入本地目录，密钥与资料处理受浏览器限制 | 仅借鉴其轻量体验 |
| 带云端账号的在线平台 | 多设备同步和在线链接方便 | 增加账号、托管、数据隔离与运维工作 | 后续再评估 |

这是一款以自我洞察为主的独立应用。Agent 工作接力、多人画像、团队管理、社交关系评价不进入首版。

## 3. 首版范围与平台接入

所有来源进入同一个标准会话模型，但必须在界面和 README 中区分原生适配与通用导入。

| 来源 | 首版方式 | 兼容承诺 |
|---|---|---|
| Codex | 用户指定目录后的只读预览与 JSONL 导入 | 支持通过公开格式和测试样例验证的用户/助手消息；保留来源、时间和分支线索 |
| Claude Code | 用户指定项目记录目录后的只读预览与 JSONL 导入 | 区分用户消息、助手内容、工具结果和注入上下文 |
| WorkBuddy | 用户指定目录后的 JSONL 适配 | 支持已验证的 message/role/content 结构；遇到未知变体报告为不支持 |
| ChatGPT、Claude 网页 | 官方导出 JSON / ZIP 导入 | ChatGPT 按选中分支处理；不能将树上全部分支伪装成顺序对话 |
| DeepSeek | 已验证导出结构适配；未知结构可转换后导入 | 只有通过测试的结构可宣称原生支持 |
| 豆包、千问办公及其他工具 | 标准 JSON、Markdown 或文本导入 | 首版不宣称原生扫描云端全部历史；提供明确的转换格式和示例 |

应用不能自行搜遍硬盘或抓取浏览器登录态。用户选择文件或目录后先预览来源、数量与时间范围，再确认导入。演示数据全部从头创作并明确标注，不读取开发者本人的私聊作为测试或发布材料。

标准文本格式以明确的 `User:` / `Assistant:` 发言边界为主；缺少可辨识角色的内容作为待确认资料，不直接参与个人事实提取。群聊和第三方人物分析不在首版范围。

## 4. 核心用户流程

### 4.1 首次体验

首页提供“体验示例”和“导入我的会话”。示例使用独立工作区，不能与用户资料混合。先展示人物概览和三项洞察，用户可展开原话、反例、时间和来源。

产品开场强调“这些话放在一起，能发现什么”。界面使用中文可读表达，避免展示实现内部名词。无 API Key 的真实导入只展示确定性资料统计和消息检索，并引导配置模型，不输出推断性画像。

### 4.2 个人档案与模式洞察

六个档案维度各自显示已知、待确认或资料不足。洞察至少包含：标题、具体观察、适用情境、支持证据、反例、其他解释、待确认问题、时间范围、分析覆盖情况。

支持四种洞察：反复卡点、成功条件、自我判断对照、阶段变化。反复模式默认需要来自至少两个不同会话的支持；独立会话数量与时间跨度公开显示，不将该门槛冒充科学置信度。单次明确自述可以作为背景事实，不能自动升级为稳定模式。

用户可以选择“符合”“部分符合”“不符合”，添加修订理由和自己的表述。系统保留旧版本和变更依据。驳回的结论不进入当前档案，也不能被后续分析静默复活；只有用户主动重新审阅才能恢复。

### 4.3 自我判断对照

用户输入一个关于自己的具体判断，例如“我是不是经常换方向”。系统从选定资料中分别寻找支持、反例和不同情境，给出有边界的解释。资料没有反例时显示“当前资料未检索到”，不能声称现实中不存在反例。

### 4.4 时间比较

用户选择两个时间区间，比较同一主题下的表达、决定和经用户确认的行动。无时间信息的资料可参与概览，但不能用于时间趋势结论。模型必须区分用户改变观点、补充说明、AI 原先理解错误和来源用途变化；无法区分时给出待确认问题。

比较结果可保存为快照，后续继续修正，不能覆盖原文。新资料出现后，旧快照标记分析日期和覆盖范围，不暗示它仍是最新状态。

### 4.5 分享与导出

支持完整档案 JSON、Markdown 报告，以及本人确认后生成的简洁分享卡。分享卡默认不包含原话、来源路径、时间地点、项目名称和会话链接；洞察文字本身仍由用户检查和选择。完整资料与分享内容分别导出，不能将整个数据库打进分享文件。

## 5. 架构与模块边界

采用 Python 3.10+ 本地服务、FastAPI、SQLite，以及 React + TypeScript 前端。开发时前端独立构建；发布包包含构建后的静态资源，普通用户运行发布包无需安装 Node.js。开发端使用 Node.js 22。具体依赖版本在实现计划中核对并通过锁文件固定。

服务默认只监听 `127.0.0.1`，不需要外部数据库。前端资源、字体与示例不依赖公共 CDN。

| 模块 | 负责什么 | 不负责什么 |
|---|---|---|
| sources | 识别、解析、标准化不同会话来源 | 不生成关于用户的心理或能力结论 |
| store | SQLite 事务、导入幂等、检索、版本与删除 | 不把所有历史无差别放入模型上下文 |
| evidence | 精确验证引用、发言人、消息版本与时间 | 不以模型自报的置信度替代证据 |
| analysis | 选择材料、分批提取、聚合档案、反例与对照 | 不执行会话中的指令或任何外部工具 |
| providers | 模型连接、超时、结构化结果与错误归一 | 不隐式上传、保存或输出用户密钥 |
| api | 本地接口、输入边界、任务状态与文件操作授权 | 不允许跨站网页任意读取本地文件 |
| web | 导入、概览、洞察、证据、变化与设置界面 | 不直接访问文件系统或调用云端模型 |

本地运行命令为 `selfdiff serve --port 8765 --data-dir <目录>`，默认端口 8765，固定监听本机；默认资料目录为用户主目录下 `.selfdiff`。目录导入命令为 `selfdiff import --source <来源> --path <文件或目录> --data-dir <目录>`；`--dry-run` 只输出预览，不写数据库。命令行与界面调用相同服务层，避免两套解析逻辑。

## 6. 数据模型与证据规则

核心实体：Workspace、Source、Conversation、Message、ImportRun、AnalysisRun、Evidence、Insight、InsightRevision、ProfileSnapshot、ProviderSettings。

- Conversation 标识包含来源与外部会话身份；Message 保留原角色、外部 ID、时间、内容摘要哈希和原文定位。
- 导入重试不产生重复消息；更新后的源记录产生新版本，不使旧引用指向不同文字。
- 分支和重放记录不能重复累计为多个独立支持案例。相同文本不必然是同一事件，不做破坏性跨平台合并。
- Evidence 绑定消息 ID、版本、精确引文和支持/反对/情境角色；引文必须是对应消息的非空子串。
- 用户自述、助手建议、第三方引文和代码/文档片段分开处理。助手生成的总结不能作为用户亲自陈述的证据。
- 个人事实需要明确用户表达；假设、提问、角色扮演不能直接记作现实背景。无法可靠分类时降为待确认。
- 用户的修订属于人工信息，保留修订出处，不伪装成历史聊天原话。
- 不生成智商、人格障碍、真实执行力排名或其他无证据的定量评分。

## 7. 模型处理流程

用户可配置 OpenAI 兼容接口或本地模型兼容接口，选择模型、地址与分析范围。密钥在服务器进程环境中使用，前端不接收明文回读；首版不提供明文密钥持久化功能。用户可通过环境变量启动服务。

配置模型后先测试连接。每次真实分析先展示将处理的来源、时间范围、消息数和预计分批数，由用户启动。估算不等于供应商账单；应用不宣称无成本或固定耗时。

流程：标准化与去重 → 用户发言为主的材料切片 → 结构化候选事实与模式 → 精确证据校验 → 反例与情境检索 → 跨片段聚合 → 再次校验 → 保存可审阅结果。

任务在本地后台执行，单进程单分析工作者，状态与进度保存在数据库中。支持取消；重启后未完成任务标记“已中断”，允许用户重试，不默默继续发送请求。批次成功结果缓存按输入哈希隔离，失败重试不会重复激活同一洞察。

历史内容作为不可信资料输入；其中出现的提示词不改变分析规则。模型不获得文件系统、联网检索或工具执行能力。

输出格式错误可进行一次限定修复；引用不存在、发言人不匹配或缺少来源的候选被拒绝并计入质量报告。部分批次失败时显示“分析不完整”和覆盖范围，不输出覆盖全部记录的总结。

## 8. 导入、删除和本地服务边界

- 单文件上传上限 50 MiB；ZIP 解压总上限 200 MiB、文件数上限 200，拒绝路径穿越、符号链接和超限内容。
- 目录扫描只处理所选来源目录内受支持的文件，不跟随链接，不读父目录；用户先预览，再导入。
- 本地服务校验 Host 与 Origin。写接口要求本机会话令牌；本地启动页完成令牌交换后不在 URL 中持续携带令牌。
- 数据库默认位于用户指定的数据目录，开发和测试使用独立临时目录。数据库、导入原文、环境文件与导出报告不进入 Git。
- 日志不输出密钥、原始会话全文或供应商请求正文；错误消息对凭据字段脱敏。
- 删除会话时删除对应消息和证据；受影响洞察、修订和快照撤下并清空关联生成内容，只保留“来源已删除”的失效元数据，不保留原文或生成的个人结论。用户可用剩余资料重新分析；被删除材料不再进入模型请求或导出。
- 不默认开启遥测或自动上传。模型调用、资料导出和公开分享均由用户主动触发。

## 9. 界面与体验

界面包括：开始页、导入与资料库、个人概览、洞察详情、判断对照、时间比较、模型设置。

视觉采用可阅读的个人研究档案风格：暖纸色、深墨色和少量强调色，证据按需展开；不把长篇报告、雷达图和未经验证的分数堆成首屏。桌面与窄屏均可操作，主要操作支持键盘，文本对比度与焦点状态清楚。演示标识在结果与分享预览中保持可见。

主要状态必须完整：空资料、示例、未配置模型、导入失败、未知格式、模型不可达、引用被拒绝、资料不足、部分分析、来源已删除、任务取消/中断。

## 10. 验证与完成标准

关键行为使用先失败后实现的测试流程。测试使用合成会话、明确预期和假的模型响应；付费模型的联通测试只有在用户配置凭据后才运行，不能以模拟测试冒充真实供应商验证。

| 检查 | 必须覆盖 |
|---|---|
| 来源解析 | 各原生来源、未知版本、错误编码、嵌套文本、工具结果、分支和重放 |
| 数据一致性 | 重复导入、增量更新、事务失败、删除及派生结果失效 |
| 洞察质量 | 伪造引文拒绝、助手输出不可归入用户、单次表达不能变成稳定模式、时间与情境不足时降级 |
| 本地安全 | 路径边界、ZIP 穿越和大小上限、跨站写请求、日志/导出不泄露密钥 |
| 人工修订 | 确认、驳回、修正、版本比较、驳回结论不会自动复活 |
| 端到端 | 示例完整体验；导入合成资料；配置假模型；生成、查看证据、修订、比较、导出和删除 |
| 发布可用性 | 前端生产构建、后端测试、安装发布包后的启动检查、README 命令实测 |

验收时提供运行截图、检查摘要和已知限制。只有检查实际通过，才能宣称相应功能完成。

## 12. 明确暂不包含

首版不承诺豆包、千问办公账户全历史自动抓取；不包含浏览器登录态提取、云同步、移动原生客户端、多人分析、心理诊断、自动公开分享和自动定时模型调用。

这些限制不改变多维度自我分析的目标；新增平台通过来源适配接口扩展。首版必须首先完成“资料 → 可信洞察 → 本人修正 → 变化对照 → 可控导出”的可用流程。
